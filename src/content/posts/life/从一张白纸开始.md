我换过很多次博客。最早是某个博客平台的默认模板，后来折腾过 WordPress，也用过一段时间的静态生成器。每一次迁移都伴随着一种错觉：换个地方，就能重新开始认真写作。

事实是，真正写下来的东西并没有变多。工具越复杂，打开编辑器的心理成本就越高。到最后，我发现自己花在调主题上的时间，远远超过写字的时间。

所以这次我给自己定了两个很简单的规则。

## 只写 Markdown

文章就是一个个 `.md` 文件，放在 `src/content/posts` 下面的两个文件夹里：工作、生活。没有后台，没有数据库，也不需要登录。

想写新文章的时候，只需要在命令行里敲一句：

```bash
npm run new -- "文章标题" --section life
```

然后打开生成的文件，从 `---` 下面开始写。图片直接拖进同名文件夹，用相对路径引用。

## 推送即发布

写完之后：

```bash
npm run ship
```

它会先构建一遍，确认没有语法错误，然后把改动提交并推送到 GitHub。剩下的交给 GitHub Actions：安装依赖、生成静态页面、部署。

通常一两分钟之后，文章就出现在线上了。

> 好的工具应该让人忘记工具本身。写作的时候，最好只剩下光标在闪。

## 这个站的样子

我保留了最初喜欢的那种感觉：白纸、留白、克制的分割线，标题很大，正文可以慢慢读。首页分成「工作」和「生活」两块，像一张摊开的纸，左边是做过的事，右边是活过的日子。

没有评论区，没有阅读量统计，也没有花哨的动画。想交流的话，写邮件给我就好。

如果你也想搭一个类似的博客，这套结构其实很容易复制：改一改配置里的名字和颜色，把示例文章删掉，就可以开始了。

写作这件事，最难的部分从来不是工具。
